# wagner-noise-extension

An extension of Wagner's (1996) evolutionary algorithm for gene regulatory networks (GRNs)
that incorporates **noisy phenotype expression**: during development every gene-gene
interaction is multiplied by random noise, so the same genotype can express different
phenotypes. The code simulates populations of GRNs under selection, mutation and
recombination, and measures fitness, stability, path length, alignment, mutational
robustness and network-motif content as a function of the noise level.

> Paper: Estrella Dzib, L. I. & Holehouse, J. (2026, April 28). How is gene-regulatory evolution affected by cell-to-cell variability? arXiv.org. https://arxiv.org/abs/2604.26082

## Model summary

- Each individual is a weight matrix `W` (genes x genes); gene states are in `{-1, 1}` by default.
- Development iterates `state -> sign(W * state)` from a fixed initial state until a fixed
  point is reached (stable), a cycle is found, or `max_steps` is exceeded (unstable). Both
  synchronous and asynchronous updating are supported.
- Noise: `W` is multiplied entrywise by random draws. The standard choice is
  `Gamma(1/θ, θ)` (mean 1, variance θ); `Bernoulli(1.0)` means no noise.
- Selection: Wagner-style (offspring survive with probability equal to fitness) or roulette.
  Fitness is `exp(-s * d)` with `d` the normalized Hamming distance to the optimal phenotype;
  unstable networks get a baseline fitness.
- Experiment 1 sweeps the noise level and tracks evolutionary dynamics and mutational robustness.
  Experiment 2 compares feed-forward-loop and feedback-loop motif frequencies in random,
  noiseless-evolved and high-noise-evolved populations.

## Repository layout

```
src/
  wagner_algorithm.jl   module BooleanNetwork: simulation (populations, development, selection)
  data_processing.jl    module CustomStats: summaries, alignment score, mutational robustness
  motif_search.py       FFL / feedback-loop motif counting (python-igraph, used through PyCall)
scripts/
  run_experiments.jl    module ExperimentHandler: Experiment 1 and Experiment 2 runners
notebooks/
  figures_generator.ipynb   runs the experiments and generates all manuscript figures
  reviewer_responses/       extra analyses prepared for the reviewers
tests/                  Julia tests (run_tests.jl) and Python tests (test_motif_search.py)
requirements.txt        Python dependencies
```

## Installation

Requirements: Julia (developed with 1.11.6) and Python 3 (developed with 3.12).

```bash
# Python environment
python -m venv venv
source venv/bin/activate            # Windows: venv\Scripts\activate
pip install -r requirements.txt
```

Install the Julia dependencies from the committed `Project.toml` / `Manifest.toml`, after
pointing PyCall to the Python environment above:

```julia
ENV["PYTHON"] = "/path/to/venv/bin/python"   # Windows: path\to\venv\Scripts\python.exe
using Pkg
Pkg.activate(".")        # from the repository root
Pkg.instantiate()        # installs the exact versions in Manifest.toml
Pkg.build("PyCall")
```

## Running the tests

```bash
julia --project=. tests/run_tests.jl   # BooleanNetwork and CustomStats
pytest tests/test_motif_search.py      # motif search
```

## Reproducing the results

Open `notebooks/figures_generator.ipynb` (launch Julia/Jupyter from the `notebooks/`
directory, with several threads, e.g. `julia -t 8`). The notebook runs Experiments 1 and 2
(`scripts/run_experiments.jl`), saves the results to `notebooks/data/experiments_results.jld2`
and writes the figures. The run-settings cell lets you shrink trials, generations and
population size for a quick smoke test; use the full values to reproduce the manuscript.
Trials run in parallel and are not seeded, so results are reproducible statistically rather
than bit for bit.
